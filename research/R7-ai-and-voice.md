# R7: AI coach and voice

## Short answer
- **AI on board, offline:** Compact 3B–4B open-weight models (**Qwen3-4B** at 2.33 GiB Q4_K_M / 3.43 GB VRAM in WebLLM, Apache 2.0; **Llama-3.2-3B-Instruct** at 1.88 GiB Q4_K_M / 2.26 GB VRAM in WebLLM; **Phi-4-mini-instruct** at 2.32 GiB Q4_K_M, MIT; **MedGemma-4B-it** at 2.32 GiB Q4_K_M via `llama.cpp`/Ollama) fit easily on an 8–16 GB laptop or tablet offline. For a hackathon demo, **Qwen3-4B** (or **Llama-3.2-3B-Instruct** on tighter VRAM) via Ollama/`llama.cpp` or browser WebLLM is the best balance of permissive license, small footprint, and short explanation quality.
- **Online vs offline & hybrid designs:** Cloud models offer stronger reasoning and zero local RAM/battery cost, while local models guarantee zero-latency offline availability on Mars (where Earth is 3–22 min away one way). Published hybrid routers (**Hybrid LLM**, **RouteLLM**) route routine queries to a small local/weak model and escalate complex queries to a strong cloud model when a link exists—so our architecture can keep local offline execution as the default and optionally use a cloud model only when online.
- **Keeping the coach safe:** Grounding an LLM with Retrieval-Augmented Generation (RAG) over curated medical sources sharply cuts hallucinations (0% vs ~40% in one oncology study) and enables explicit refusal when evidence is missing, while **guardrail-first** workflows catch safety-critical escalations. However, peer-reviewed evaluations also show authentic citations alone do not guarantee safe conclusions—fixed code rules must own all thresholds, red flags, and escalation wording.
- **NASA's own work:** NASA's Human Research Program (HRP) and Google evaluated a **Crew Medical Officer Digital Assistant (CMO-DA / "Doc in a Box")** using Llama 3.1 (8B/70B/405B) across three simulated Earth-Independent Medical Operations (EIMO) scenarios scored by physicians and an astronaut via OSCE: **Ankle Injury 88%**, **Ear Pain 80%**, **Flank Pain 74%**—scoring higher on diagnosis than on therapeutic recommendations. NASA's 2026 HRP AI work also integrates Butterfly iQ3 ultrasound, AMOS procedures, and UpToDate medical content.
- **Speechmatics vs offline voice:** Speechmatics Real-Time STT streams over WebSocket (`@speechmatics/real-time-client` JS/TS SDK) with **0.7–4.0 s** `max_delay` across **63** language options (and automatic 56-language switching in Melia 1 / Oak 1 medical). **$500** in credits buys **~1,250–3,333 hours** of cloud Real-Time STT (**$0.15–$0.40/hr**), and Speechmatics also offers a preview **Text-to-Speech** API (**$0.011 / 1k chars** after 1M free chars). Crucially, Speechmatics **on-prem/offline containers require an Enterprise contract** (not usable on self-serve credits) and Agent STT (`linden-1`) is SaaS-only—so offline Mars voice must use **Vosk** (40 MB small / 128 MB lgraph, Apache 2.0, `vosk-browser`) or **whisper.cpp** (`tiny`/`base`, MIT) for STT, plus **`SpeechSynthesis`** (`localService` voices) or **Kokoro-82M** (82 MB ONNX, Apache 2.0) / **Piper** (60 MB ONNX, GPL-3.0) for TTS; standard browser `SpeechRecognition` sends audio to cloud servers and fails offline unless experimental `processLocally` local packs are supported and pre-installed.
- **Where voice helps most:** Randomized trials and meta-analyses show **audio/voice-guided checklists and cognitive aids** improve resuscitation sequence compliance, shorten time to critical actions, and improve overall performance (`SMD 1.16`), though **visual + audio combined** outperforms audio alone and poorly designed prompts can overload untrained users—supporting short voice commands (`"next step"`, `"repeat"`, `"start timer"`) paired with our high-contrast visual cards during hands-busy tasks (CPR, blood pressure cuff).

## What this means for the app (proposal)
- **Simplest offline-first AI coach design (Should):**
  1. **Deterministic rules first:** Code computes Sara's PVT drift, BP category, action-card state, and emergency red flags. The LLM **never** calculates thresholds or diagnoses.
  2. **Strict local RAG over verified chunks:** Index our verified R1–R8 JSON/Markdown cards (NASA HRP risks, Basner PVT-B science, AHA BP/first-aid rules, Mars comm-delay facts). Retrieve top 2–3 chunks by section/topic ID and require the model to cite `[Source ID]` inline; if retrieval similarity/match is empty, return a fixed abstention (*"I only answer from verified mission medical cards and don't have a verified source on that."*).
  3. **Fixed escalation wrapper:** Any red-flag state or symptom keyword (`chest pain`, `shortness of breath`, `fainting`, `unequal pupils`, `>180/120`) triggers a deterministic UI banner *above* the AI reply: *"Not a medical diagnosis. Alert crew / CMO now and queue an async report to Earth—do not wait for a 40-minute reply."*
  4. **Runtime choice for demo:** Run **Qwen3-4B** (Apache 2.0, 2.5 GB) via local **Ollama** behind our Node.js backend (easiest to swap with Claude API in a 1-env-var hybrid router: `ONLINE_CLOUD` when reachable vs `OFFLINE_LOCAL` default), or **Llama-3.2-3B-Instruct** in-browser via **WebLLM** (`2.26 GB` VRAM) for a zero-backend offline browser demo. Keep **MedGemma-4B** as a named pitch/upgrade option rather than a WebLLM target.
- **Simplest offline-first voice design (Later / Pitch + optional demo toggle):**
  - **Voice output (TTS):** Use browser **`SpeechSynthesis`** filtered to `voice.localService === true` for zero-download offline step readback during BP measurement and emergency mode (pairs audio + visual steps, matching the meta-analysis finding that visual + audio beats audio alone). Mention **Kokoro-82M** (82 MB ONNX, Apache 2.0) as the higher-naturalness offline upgrade.
  - **Voice input (STT) for hands-busy commands:** Keep commands constrained to 5–6 short phrases (`"next step"`, `"previous"`, `"repeat"`, `"start timer"`, `"stop"`, `"alert crew"`). Run **`vosk-browser`** (`vosk-model-small-en-us-0.15`, **40 MB**, Apache 2.0) or **`whisper.cpp` (`tiny.en` / `stream.wasm`, 75 MiB, MIT)** fully offline—never rely on standard `SpeechRecognition` because Chrome sends audio to the cloud.
  - **Where Speechmatics ($500 credits) fits honestly:** Do **not** claim Speechmatics cloud APIs work offline on Mars, and note that Speechmatics on-prem containers require an **Enterprise contract** (unavailable on self-serve credits). Use Speechmatics Real-Time (`@speechmatics/real-time-client` + **`oak-1`** medical or **`linden-1`** agent model) only as an optional **Earth-side / connected-bench high-accuracy medical dictation mode** (e.g., transcribing Sara's post-incident voice log when a link is available, with offline `whisper.cpp`/`Vosk` fallback).
- **What to build first vs pitch only:**
  - **Build first (Must, zero AI/voice dependencies):** Fixed-rule check-in, personal normal zone chart, static verified action cards, guided BP timer/steps, and offline emergency step cards (with optional 10-line browser `SpeechSynthesis` "Read step aloud" toggle if time permits).
  - **Build second if time allows (Should):** Local RAG AI coach (`Qwen3-4B` via Ollama or Claude API with local Ollama fallback) grounded strictly in our verified action-card knowledge base, with source badges and deterministic red-flag escalation.
  - **Pitch only (Later):** Hands-free offline voice command control (`vosk-browser` / `whisper.cpp` + `Kokoro-82M`) for CPR/BP cuffs, multimodal CMO-DA–style ultrasound/sensor fusion, and Speechmatics `oak-1` medical voice-log transcription when connected.
